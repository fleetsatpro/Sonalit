# Convoy System

## Purpose

Teaches the convoy management system — the core operational workflow of Sonalit. Convoys represent organized vehicle movements with security oversight, CFO (Convoy Field Officer) monitoring, seal integrity tracking, and route risk management.

## When to Activate

Any work involving convoys, CFO operations, trucks, seals, reports, or route planning.

## Convoy Lifecycle State Machine

```
planned → active → completing → completed
planned → cancelled
active → completing | completed | aborted | cancelled
completing → completed | aborted | cancelled
completed, aborted, cancelled → (terminal)
```

Defined in `VALID_TRANSITIONS` in `controllers/convoyController.js`.

On transition to `active`: sets `departure_time`.
On completion: sets `arrival_time`, enqueues `generateArchive` on `convoyArchiveQueue`.

## Key Entities

### Convoy

Table: `convoys`

Key columns: `name`, `reference`, `region` (Kenya/DRC/Tanzania/Mali), `priority` (low/medium/high/critical), `route_origin`, `route_destination`, `status`, `departure_time`, `arrival_time`, `estimated_arrival`, `timezone`, `seal_count_per_truck`, `archive_pdf_url`

### Convoy Trucks

Table: `convoy_trucks`

Each truck has: `position` (ordinal in lineup), `vehicle_id`, `driver_name`, `driver_phone`, `registration`

### CFO (Convoy Field Officers)

Table: `convoy_cfos`

Links a `cfo_user_id` to a convoy with a `guardian_device_id`. CFO roles: `primary`, `backup`, `observer`.

CFO-to-truck assignments: `convoy_cfo_truck_assignments`

### Seals

Table: `convoy_seals`

Columns: `convoy_truck_id`, `seal_position`, `rfid_code`, `session`, `status`, `report_date`

### Route Waypoints

Table: `convoy_route_waypoints`

Dispatcher-entered towns/checkpoints: `seq`, `name`, `lat`, `lng`

## CFO Photo Evidence

Tables: `convoy_truck_photos`, `photo_uploads`

Photo phases: SOD (Start of Day), EOD (End of Day), plus seal check photos.

**EXIF anti-spoofing**: `guardianCfo.js` validates photo EXIF GPS coordinates against claimed location — rejects if >500m discrepancy.

Photo validation: max 8MB, image/jpeg or image/webp only.

EOD finalization sweep runs every 15 minutes — queues `generateReport` for complete/partial reports.

## Daily Reports

Table: `convoy_daily_reports`

Columns: `convoy_id`, `report_date`, `required_photo_count`, `received_photo_count`, `status`, `pdf_url`, `content_hash`, `pdf_data`, `generated_at`

Generated by `convoyReportWorker.js`. PDF includes photos, seal status, route progress. Uploaded to R2. Content hash prevents duplicate regeneration.

## 4D Corridor Evaluation

File: `services/geofence/corridor.js`

Route corridor with time dimension. `evaluateCorridor()` checks:
- **Space**: cross-track distance from planned route
- **Time**: schedule position (ahead/behind)

Returns: `off_route` (high severity), `behind` (medium), `ahead` (low), `on_track` (ok)

Corridor deviation >= 4x corridor width = critical severity.

Table: `convoy_route_corridors` (convoy_id, route_line, width_km, active)

## Auto-Corridor Planning

Geocodes origin/destination, requests multiple road alternatives, scores each against live risk zones using `rankRoutes()`, stores safest viable route.

## Day Plans

Tables: `convoy_day_plans`, `convoy_day_plan_waypoints`

CFO daily plans with up to 20 waypoints (radius 50-10000m). Tracks waypoint arrival (`reached_at`, `reached_lat`, `reached_lng`).

## Broadcasts

Table: `convoy_broadcasts`

Channels: `app`, `whatsapp`, `sms`, `email`. Statuses: `pending`, `sent`, `partial`, `failed`.

Uses canned messages (`canned_messages` table) for rapid dispatch.

## Backend Routes

File: `backend/src/routes/convoys.js`

Key endpoints:
- CRUD: `GET/POST/PUT/DELETE /convoys`
- Status: `PATCH /:id/status` (follows state machine)
- Trucks: `POST/DELETE /:id/trucks`
- CFOs: `POST/DELETE /:id/cfos`, `PATCH /:id/cfos/:cfoId/device`
- Assignments: `POST/DELETE /:id/cfo-assignments`
- Waypoints: `GET/PUT /:id/route-waypoints`
- Reports: `GET /:id/reports`, `GET /reports/overview`

Authorization: `admin`, `dispatcher` for mutations; `analyst` for read-only report access.

## Realtime

NATS subject: `convoy.updated.<orgId>` (ConvoySchema payload)
Centrifugo: publishes to `org#<orgId>` channel

## Do

- Follow the state machine for status transitions
- Validate EXIF GPS on CFO photos
- Use the corridor evaluation for route monitoring
- Maintain seal integrity tracking
- Use `authorize('admin', 'dispatcher')` for mutations

## Don't

- Allow arbitrary status transitions — follow the state machine
- Skip EXIF validation on photo uploads
- Create convoys without a timezone
- Ignore the content hash when regenerating reports
- Mix convoy entities with CDS entities
